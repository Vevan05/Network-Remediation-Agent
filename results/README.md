# results/

Raw experiment output. Every number in the top-level README.md comes from these files.

## Run files (one JSON object per line)

| file | what it is |
| :--- | :--- |
| `runs_final_benchmark.jsonl` | **v1** LLM benchmark (12 scenarios x 3 repeats x 3 policies = 108 rows). Pre-dates the shared-dependency testbed and the v2 risk formula. Kept as the baseline for the escalation audit: `python -m eval.audit results/runs_final_benchmark.jsonl` |
| `runs_benchmark_v2.jsonl` | **v2** LLM benchmark: same design, new testbed (shared dependency), v2 risk formula, measured collateral damage, operator seeded per diagnosis |
| `runs_unsafe_heuristic.jsonl` | Heuristic agent with a 30% error rate, 120 diagnoses. The stress test that makes unsafe (collateral-causing) actions reachable |
| `runs_unsafe_heuristic_50.jsonl` | Same with a 50% error rate, 60 diagnoses |
| `runs_pilot.jsonl` | Earlier pilot run (v1 testbed) |
| `_pre_pairing_fix/` | The v2 runs *before* the paired-design fix (one operator shared across the whole run rather than seeded per diagnosis). A local archive only — it is git-ignored and is **not** part of the published results. |

All of these are committed: they are the evidence behind every number in the
top-level README.md, and `eval/audit.py`, `eval/sweep.py` and `eval/report.py`
read them, so a clone has to contain them for any claim to be checkable.
`results/remediation.db` is the opposite case — it is runtime state (pending
approval plans and the UI event stream) and is git-ignored.

### Row schema

| field | meaning |
| :--- | :--- |
| `run_id` | groups the three policy runs of ONE diagnosis (paired design) |
| `mode` | `full-auto` / `adaptive` / `full-human` |
| `plan` | the full proposed plan, including the `evidence` the agent saw |
| `plan_correct` | the action is in the ground-truth `FIX_MATRIX` for the injected fault |
| `risk_score` | the score of the formula that was live (`risk_version`) |
| `risk_score_v1`, `risk_score_v2` | both formulas, always, so every run carries its own ablation pair |
| `routing` | `auto_execute` / `require_approval` |
| `verdict` | `auto` / `approve` / `reject` |
| `action_effective` | did the action achieve its intended effect? |
| `collateral`, `unsafe_action` | measured collateral damage in a non-target service |
| `recovered` | did the TARGET service recover? |
| `decision_latency_s` | wall-clock time the agent spent diagnosing |
| `mcp_calls` | MCP tool calls per incident (communication overhead) |
| `mttr_s` | decision latency + human wait + execution + manual penalty (null if not recovered) |
| `error` | non-null if the run aborted |

## Sweeps and analyses

| file | what it is |
| :--- | :--- |
| `sweep_live_v1.csv`, `sweep_live_v2.csv` | threshold sweeps that re-execute the recorded plans in Docker at each threshold |
| `sweep_replay_heuristic.csv`, `sweep_replay_heuristic_50.csv` | offline replay sweeps of the two stress sets |
| `risk_weight_sensitivity.csv` | the v2 rubric weight swept from 0.0 to 0.8 |
| `figs/` | figures regenerated by `python -m eval.metrics <runs file>`; committed so the README renders them |

The offline replay and the live sweep agree exactly on `success_rate`,
`human_rate`, `unsafe_rate` and `failures` at every threshold — that is how the
replay was validated before being used for the 120-diagnosis sweeps.

## Reproducing a number

```bash
python -m eval.report results/runs_benchmark_v2.jsonl   # everything at once
python -m eval.audit  results/runs_benchmark_v2.jsonl   # escalation audit only
python -m eval.sweep  results/runs_benchmark_v2.jsonl   # threshold sweep only
```
